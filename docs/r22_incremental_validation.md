# Pressure21 incremental scheduler and bounded validation

> **Release inputs.** The recorded five-case audit is included as `artifacts/pressure21_linear_audit_final_20261106/audit.json`; rerunning requires the specified development and scale inputs and frozen model.

The 21-case paired resource measurement is documented in [Pressure21 paired resource benchmark](r22_resource_benchmark.md).

`src/evcharging/simulation_schema.py:schedule_pressure21` accepts aligned records for the currently connected vehicles in the requested processing order. Its callback receives the compact rank and compact urgency vector; the caller can map the rank through `indices` to the original identifier. The full-day `simulate` adapter preserves its prior callback contract: original vehicle identifier and full-length urgency. The compact entry point constructs prefix and suffix sums for residual energy, power, bounded urgency, remaining slots and urgency times power, then forms each state in constant time. It accumulates the preceding proposals after clipping to [0, 1] and before SPP. Compact SPP retains the supplied order. SoC is fixed while proposals are formed and is updated after SPP by the caller. Empty connected sets are supported.

The compact scheduling calculation and connected SoC update take `O(N_t)` per slot, bounded by `O(N_cp)` for `N_cp` charging piles with at most one connected EV per pile, given the ordered connected records and a fixed-size policy; maintaining the connected set is the caller's responsibility. The full-day simulator uses arrays of length `M` to discover connections, maintain SoC and provide its historical outputs, so its per-slot work is `O(M + N_t)` and stored trajectories also depend on `M` and the horizon. `build_state` and `refined_state` remain the repeated-aggregation references, and `pressure_reference=True` selects that path in the simulator.

A bounded single-process, single-compute-thread audit used the frozen 11002 checkpoint and existing inputs: development seed 64000 at 200 EV and 600/800 kW, and fixed-day scalability seeds 111000–111002 at 3000 EV and 12000 kW. Both paths were simulated in closed loop using the same inputs. `artifacts/pressure21_linear_audit_final_20261106/audit.json` records each input, model and executed source SHA-256, maximum absolute error for every compared array, costs, unfairness, failed-vehicle counts, physical residuals, tolerance and diagnostic elapsed times. The comparison tolerance is `1e-6`, physical tolerance `1e-8` and departure SoC tolerance `1e-4`. Across the five cases the largest state difference was `8.44e-15`; raw and corrected actions, SoC, cost, unfairness and decision records were identical in these runs. Both implementations met all vehicle targets. The largest station-capacity residual was `7.28e-12` kW. Changed floating-point summation order means bitwise state identity is not assumed in general.

To repeat the audit in a fresh output directory, run `uv run python scripts/audit_pressure21_linear.py --output artifacts/<new-directory>` from the repository root.
