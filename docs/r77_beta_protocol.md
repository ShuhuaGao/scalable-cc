# Matched expert-weight sensitivity workflow

> **Release inputs.** The original beta 0.3 expert cases and cache are included. The beta 0.1 and 0.5 expert cases and their models are generated by this workflow and require Knitro; compact results are in `results/pressure21_v1/r77/`.

This workflow uses the original 360 training and 90 validation cases for each of beta 0.1, 0.3, and 0.5. The original audited beta 0.3 experts and frozen seed 11002 model are retained. New experts at the other two weights use four multistarts and a per-window limit of three seconds per daily vehicle, with one solver thread per worker. The four workers form disjoint shards of the frozen 900-case manifest. Each new policy uses seed 11002 and the existing Pressure21 teacher and continuation configuration.

From the repository root, in a separate clean working copy with the audited original expert assets and no existing `artifacts/runs/r77/`, run:

```text
uv run python scripts/r77_prepare.py
uv run python artifacts/runs/r77/worker.py --shard 0
uv run python artifacts/runs/r77/worker.py --shard 1
uv run python artifacts/runs/r77/worker.py --shard 2
uv run python artifacts/runs/r77/worker.py --shard 3
uv run python artifacts/runs/r77/prepare_train.py --beta 0.1
uv run python artifacts/runs/r77/prepare_train.py --beta 0.5
```

The four shard commands can run concurrently when the license permits. Wait for them before auditing and training, or start `finish.py` with the four worker process IDs to begin each audit after its expected reports appear. Capture separate worker and manager standard-output and error logs. Existing incomplete or failed cases are retained and skipped, not replaced. The audit blocks training if any case fails or is missing. Investigate failures and preserve their output before a separately documented retry.

`manifest.json` and `frozen.json` record matched cases and generation-source hashes. The audit checks those hashes, per-case inputs, decisions, physical residuals and labels before building the Pressure21 cache and training. Each model summary records the hashes and paths of its expert manifest, audit, cache manifest and selected checkpoint. The manifest records the worker count and computing environment.

The beta 0.1 expert audit records 15 windows with Knitro status -205
(`KN_RC_INFEAS_VAR_BOUNDS`) and no completed multistart, rather than an optimal
termination. Their independently checked residuals are at most 7.71e-9 and
meet the original 1e-4 acceptance threshold. Window-level details are in
`results/pressure21_v1/r77/expert_training_inventory.json`. This feasibility
audit is distinct from the subsequent learned-policy evaluation.

## Matched evaluation

After training, create a model manifest for each weight using the schema in `artifacts/runs/pressure21_v1/evaluation/r77_beta_manifests/`. The published manifests identify the three recorded models. In a separate working copy without the existing `artifacts/runs/pressure21_v1/evaluation/r77_beta/` output directory, evaluate each policy from the repository root:

```sh
uv run python scripts/evaluate_r77_beta.py --manifest artifacts/runs/pressure21_v1/evaluation/r77_beta_manifests/beta_0.10.json
uv run python scripts/evaluate_r77_beta.py --manifest artifacts/runs/pressure21_v1/evaluation/r77_beta_manifests/beta_0.30.json
uv run python scripts/evaluate_r77_beta.py --manifest artifacts/runs/pressure21_v1/evaluation/r77_beta_manifests/beta_0.50.json
```

For newly trained models, update the corresponding checkpoint and training-provenance paths and SHA-256 values in fresh manifest files. Each evaluation verifies model provenance and writes 79 cases. See [the results and summary commands](r77_beta_results.md).
